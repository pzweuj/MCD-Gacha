# 设计文档：概率、保底与组合生成

## 1. 稀有度与概率

基础权重（`src/mcd_gacha/data/banners.json`）：

| 稀有度 | 基础概率 | 语义 |
|--------|---------|------|
| SSR | 5% | 预算内价值最大化 + 最优券（"欧皇"组合） |
| SR | 25% | 经典热销正餐（主 + 配 + 饮） |
| R | 60% | 规矩的一顿（1+1 随心配 / 主 + 配角） |
| N | 10% | 抽象整活（意料之外的搭配艺术，笑点担当） |

## 2. 保底机制

- **每卡池独立计数**：连续 9 发未出 SSR 后，第 10 发**强制 SSR**；出 SSR 后计数清零；
- 十连 = 顺序 10 次单抽，共享同一计数器；
- 不变量：任意连续 10 抽窗口内必然包含至少 1 次 SSR。

### 2.1 概率透明声明（重要）

基础 5% 叠加 10 发硬保底后，**SSR 有效出率 ≈ 12.5%**（平均约 8 抽一金）。
本项目的立场是**如实披露**而非隐藏机制：内置 `simulate` 蒙特卡洛自证命令：

```bash
mcd-gacha simulate -n 100000 --seed 42
# SSR 实测 ≈ 12.40%，最大间隔 10 抽，保底触发占比 ≈ 7.9%
```

推导：以 10 发为周期，未出金概率为 0.95^9 ≈ 0.63，故每周期 SSR 概率 = 1 − 0.95^9 ≈ 37%，
期望间隔 = 1/0.125 ≈ 8.06 抽。

## 3. 组合生成算法

所有策略统一出口经过「真实核价 + 预算校验」（`compute_price().paid_cents ≤ budget`），
组合件数上限 3（符合真实点餐习惯，倡导适度点餐）。

### R：经典保底（regenerative greedy scoring）

枚举 1–3 件组合，评分偏好：经典/超值标签、件数 2、预算利用率 ≥ 0.8、不含奇怪搭配。

### SR：稳稳的幸福

在 R 的枚举基础上增加**完整度约束**：必须含主食（汉堡或随心配套餐），
评分偏好「主 + 配 + 饮」三件套与预算利用率 [0.8, 1.0]。

### SSR：欧皇时刻（0/1 背包）

形式化为**预算约束下的价值最大化**：

1. 枚举券方案：不使用券 / 每种满减券（容量放宽 = 预算 + 券额）/ 每种单品券（必含目标商品）；
2. 每种方案求解 0/1 背包「容量内原价最大」（`optimizer.best_subset`，DP 复杂度 O(n × capacity)）；
3. 候选组合经核价过滤（券后实付 ≤ 预算）后，取**原价价值最大**者。

打工人 UP 池的 SSR 强制包含 `premium` 锚点（巨无霸/安格斯），确保"保底发必是硬菜"。

### N：隐藏款（抽象艺术）

枚举允许重复的组合（如「圆筒 × 3」），按「离谱度」评分：

- 类别跳跃（≥3 类混搭，如 汉堡 + 咖啡 + 冰淇淋）；
- 无正经主食 / 全是饮料 / 全是咖啡；
- 咖啡配炸物的神秘搭配；
- 分毫凑满预算（利用率 ≥ 95%）。

N 档的定位是「有趣但能用」：数量克制、预算内、适度点餐。

## 4. 选择策略（软加权随机）

每组候选按评分的**软加权随机**抽样（`exp((score−max)/τ)`，τ=1）：

- R/SR/N：在评分 top-12（N 为 8）内软加权随机——高分组合更常出现，低分组合保留惊喜；
- SSR：在「**近优带**」（原价 ≥ 最优的 88%）内按优势指数加权随机，
  保留"金光最豪华"定位的同时避免同预算下永远出同一套组合（该行为有专项测试兜底）。

## 5. 预算与券语义

- 金额内部一律使用「分」（int），杜绝浮点误差；
- 单券最优：一单只核销一张最优惠的券（与真实点餐惯例一致）；
  - 满减券：小计 ≥ 门槛时整单减固定额；
  - 单品券：组合含目标商品时立减（每单一次）。
- 预算下限保护：用户预算低于卡池定位时抬至卡池下限；上不封顶。

## 6. 重铸（Reforge）

抽卡结果不满意时，可对组合中的**指定一件**执行重铸：

- 只替换指定件，其余保持（同品类约束：汉堡位换汉堡、饮品位换饮品）；
- **优先「升级/平价」替换，降级仅作兜底**——重铸不亏；
- **不消耗保底进度、不改变稀有度**（重铸是"工艺"，不是抽卡）；
- 预算不变：替换后券后实付 ≤ 预算（本地筛用券后价，含未知额外部券时放宽余量，最终由核价裁决）；
- 状态：最近一次结果持久化于 `state.json` 的 `last_result`，支持跨进程连续重铸。

## 7. 数据流

```
Skill / CLI → Engine
  ├── roll_rarity()        # 保底优先 + 加权抽样
  ├── generate_*()         # 四档组合生成（本文件第 3 节；候选收集可缓存）
  ├── source.calculate_price()  # 核价（mock 复刻 / MCP 真实）
  ├── source.list_nutrition()   # 热量聚合
  ├── reroll(slot)         # 重铸（第 6 节；读取 state.last_result）
  └── state.save()         # 保底计数 / 历史 / last_result 持久化
```

## 8. 交互层（Skill）

本项目只提供单一形态——**AI Skill**（`SKILL.md`）。Skill 是交互层，负责触发识别、
命令编排、结果转写与可点击收尾；所有概率 / 保底 / 组合生成 / 核价逻辑仍由底层
Python 引擎统一承载（`src/mcd_gacha/`），Skill 通过 `uvx` 调用引擎命令取值。
参数（概率 / 卡池 / 预算）以 `src/mcd_gacha/data/banners.json` 为单一真源。
